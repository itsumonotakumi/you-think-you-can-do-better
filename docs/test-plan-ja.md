# テスト計画書

インシデントシミュレーター「じゃ、あなたがやってみてよ」（You Think You Can Do Better?）

- 版：0.1（初版ドラフト）
- 作成日：2026-11-08
- 作成：いつもの匠
- 前提文書：[要件定義書](requirements-ja.md)、[概要設計書](basic-design-ja.md)、[詳細設計書](detailed-design-ja.md)

---

## 1. 目的

このツールで一番困るのは、「正解が間違っている」ことと「実在の企業を傷つける」ことである。バグよりもこの2つを重く見る。テストは次の4つを確かめる。

1. ゲームが仕様どおりに動くこと（進行、採点、プレイ回数と初回補正、保存、多言語、演出とサウンド）
2. シナリオの中身が正しいこと（根拠、細目の量、ミスリードの量、点数の整合）
3. 実在の企業・人物を特定できず、傷つけないこと
4. 狙った体験になっていること（苦しいが、やり切ると爽快）と、目的（インシデントレスポンスを学び、興味を持ち、批判と対応を理解できるようになる）が果たせていること

## 2. 範囲

| 対象 | 含む | 含まない |
| --- | --- | --- |
| アプリ | 画面、進行、採点、ゲージ、ミスリード発火、保存、多言語、印刷 | 複数人で分担するモード（当面は対象外） |
| シナリオ | 10シナリオ×4ロールのデータ | 未公開のシナリオ |
| 公開 | GitHub Pages 上での動作 | 外部の法務レビュー（行わない方針） |

## 3. テストの種類と時期

| 種類 | 内容 | 時期 |
| --- | --- | --- |
| シナリオ自動検査 | シナリオYAMLの形式と中身のルールを、ビルド時に機械的に確認 | シナリオを追加・変更するたび（GitHub Actions で自動実行） |
| 単体テスト（Vitest） | 時計、採点、ゲージ、臆病ゲージ、遅れて来る効果、記者会見の制限時間、エンディング判定 | 実装中、変更のたび |
| 結合テスト | シナリオを読み込み、最初から最後まで通す | 機能がそろった時点 |
| 画面テスト（Playwright） | 画面の表示と操作、スマホとPC、日本語と英語 | 結合テストの後 |
| 内容レビュー | セキュリティの専門家目線で、正解と根拠が妥当か | シナリオ公開前 |
| セルフチェック | 権利・名誉毀損のチェックリスト | シナリオ公開前 |
| プレイテスト | 対象ユーザーに遊んでもらい、体験を確かめる | 初版公開前 |

## 4. シナリオ内容の検査（自動）

シナリオを公開する前に、次をすべて満たすことを機械的に確かめる。1つでも満たさなければ公開しない。

| ID | 検査項目 | 基準 |
| --- | --- | --- |
| C01 | 形式 | 必須の要素（メタ情報、会社設定、発端、フェーズ、判断ポイント、エンディング）がそろっている |
| C02 | 判断ポイントの数 | ロールごとに15〜25（経営者ロールは15〜18） |
| C03 | 細目の数 | ロールごとに80以上 |
| C04 | 細目の点数 | 1つあたり ±1〜20（致命的な失点と「信頼を増やす」は例外として区分で管理） |
| C05 | 点数区分の範囲 | 各選択肢の点数が、その区分の範囲（例：維持は+10〜+30）に収まっている |
| C06 | 根拠の紐づけ | すべての細目と選択肢に根拠IDがあり、根拠データに存在する |
| C07 | ミスリードの量 | 判断ポイントの半分以上に、誤った対応を勧める声が1つ以上ある |
| C08 | ミスリードの型 | シナリオ全体で、12種の型のうち8種以上を使っている |
| C09 | 臆病への批判 | 「保留」系の選択肢を連続で選んだときの批判がある |
| C10 | 正しい対応の直後の批判 | 正しい対応の直後に、一時的に批判が増える場面が1つ以上ある |
| C11 | 到達可能性 | 各ランク（S〜D）に到達する選び方が少なくとも1つある |
| C12 | Sランクの条件 | 致命的な失点を1つでも取るとSに届かない |
| C13 | 行き止まりがない | どの選び方をしてもエンディングに着く |
| C14 | 文言の欠け | 対応言語すべてに文言がある |
| C15 | 法定期限 | 期限の数値が根拠データ（最新の確認日のもの）と一致している |
| C16 | 実名の混入 | 実在の企業名・サービス名・人物名の禁止リストに当たる語がない |
| C17 | YAMLの検査 | YAML の書式誤りやスキーマ違反があると、ビルドが失敗し、ファイル名と行番号が表示される |
| C18 | 想定プレイ時間 | 選択肢の文章量と判断ポイントの数から見積もった所要時間が、ロールの目安（30〜60分、経営者は30分前後）に収まる |
| C19 | 犯罪者の注記 | 冒頭、攻撃者が登場する場面、全エンディングに「悪いのは攻撃者」の注記がある |
| C20 | 実在企業との比較 | 実在企業と点数・ランクを比べる文言がない |
| C21 | 高得点の注記 | スコアを出す画面の共通文言に「高得点でも現実の対応が正しいとは限らない」注記があり、シナリオ側で上書きされていない |
| C22 | 音素材 | すべての音が素材一覧にあり、ファイルが存在し、出典と利用条件が書かれている |

## 5. 機能テスト

### 5.1 進行

| ID | 確認すること |
| --- | --- |
| F01 | 行動ごとに所要時間が消費され、時計が15分刻みで進む |
| F02 | 決まった時刻に外部の出来事（報道、攻撃者の要求、問い合わせ）が起きる |
| F03 | 法定期限を過ぎると、該当の減点が入る |
| F04 | ロールごとに、見える情報と選べる選択肢が違う |
| F05 | 役割を越えた行動（担当者の独断公表など）が減点になる |
| F06 | 体力ゲージが0になると、判断ミスが起きやすくなる演出が入る |

### 5.2 採点

| ID | 確認すること |
| --- | --- |
| F11 | 方針の点数と細目の点数が、それぞれ正しく加算される |
| F12 | 細目の例（No.4 第1報）で、全部取ると+69、最悪で−65になる |
| F13 | 致命的な失点の後、「信頼を増やす」の加点が低い代わりの点になる |
| F14 | 誘導に乗った選択で、その場の炎上度が下がり、数フェーズ後に減点が来る |
| F15 | 臆病ゲージが2回・3回・4回以上で、−10・−20・−40になる |
| F16 | 便乗商法の選択が「信頼を傷つける」で減点になる |
| F17 | エンディングのランクが、点数と致命的な失点の有無で正しく決まる |
| F18 | 記者会見で、記録を残していたときだけ使える回答が出る |
| F19 | 記者会見の制限時間が1問ごとに数えられ、時間切れで「確認しておりません」扱い・−30点になる |
| F20 | 記者会見中に記録を開いても、制限時間が止まらない |

### 5.3 振り返りレポート

| ID | 確認すること |
| --- | --- |
| F21 | すべての判断について、点数・根拠・取れた細目・取りこぼした細目が出る |
| F22 | 「あなたを動かした声」に、選択の直前に出ていた誘導の声が出る |
| F23 | プロローグの入力と実際の公表時刻が並んで出る |
| F24 | 印刷用の表示で、内容が切れずにPDFへ保存できる |

### 5.3.1 プレイ回数と初回補正

| ID | 確認すること |
| --- | --- |
| F25 | プレイ回数がシナリオ×ロールごとに数えられる |
| F26 | 「n回目」が、上部バー、エンディング、振り返りレポート、印刷、クリア状況のすべてに出る。消したり隠したりできない |
| F27 | 公式スコアが素点×係数（1回目×1.2、2回目×1.0、3回目×0.8、4回目以降×0.6）になる。素点がマイナスのときは係数を掛けない |
| F28 | ランクが公式スコアで決まり、同じ素点なら初回の方が高いランクになる |
| F29 | クリア状況の代表が初回記録で、2回目以降の最高が「最高（n回目）」として併記される |
| F30 | 2回目以降のエンディングに「現実の事件に2回目はありません」の一文が出る |

### 5.4 保存

| ID | 確認すること |
| --- | --- |
| F31 | 途中で閉じても、続きから再開できる |
| F32 | クリア状況と最高ランクが残る |
| F33 | 保存データの消去で、すべて消える。消去の前に「プレイ回数と初回記録も消えます」と確認が出る |
| F34 | 保存が使えない環境でも、最後まで遊べる |
| F35 | シナリオの版が上がったとき、古いデータの扱いを選べる |
| F36 | 保存内容がブラウザの外に送られていない（通信を監視して確認） |

### 5.5 多言語

| ID | 確認すること |
| --- | --- |
| F41 | 日本語と英語を切り替えると、画面とシナリオ本文がすべて切り替わる |
| F42 | 未翻訳の文言が「未翻訳」と分かる形で出る（日本語に戻らない） |
| F43 | 英語で長くなる文言でも、画面が崩れない |

### 5.6 演出とサウンド

| ID | 確認すること |
| --- | --- |
| A01 | タイトル画面で「はじめる」を押すまで音が鳴らず、押した後にBGMが鳴る |
| A02 | 場面（フェーズ、深夜帯、記者会見、エンディングのランク）に合わせてBGMが切り替わり、1.5秒かけてつながる |
| A03 | 炎上度40・70を境に、BGMの重なる音が増減する。継ぎ目で音が途切れない |
| A04 | 選択の直後に、正誤で違う音や演出が出ない。誘導の声と正しい声で効果音と見た目が同じ |
| A05 | 着信・通知・期限の警告などの音に、必ず画面の文字表示が伴う。ミュートでも内容が分かる |
| A06 | BGMと効果音の音量を別々に変えられ、ミュートが効き、設定が保存される |
| A07 | 「演出を減らす」設定、または端末の「動きを減らす」設定で、揺れ・フラッシュ・早送り・タイプ表示が止まる |
| A08 | フラッシュなどの明滅が1秒に3回を超えない |
| A09 | 同じ効果音が重なっても4つまでに抑えられる |
| A10 | 音の読み込みに失敗しても、音なしで最後まで遊べる |
| A11 | クレジット画面に、素材一覧のクレジットがすべて出る |

## 6. 非機能テスト

| ID | 種類 | 確認すること |
| --- | --- | --- |
| N01 | ブラウザ | PC とスマホの主要ブラウザの最新版で動く |
| N02 | 表示 | スマホ幅で区画が縦に並び、世間の声と記録がタブで切り替わる |
| N03 | 速度 | シナリオの読み込みと画面の切り替えが、もたつかない |
| N04 | アクセシビリティ | キーボードだけで最後まで遊べる。挿絵に代替テキストがある。ゲージに数値が出る |
| N05 | セキュリティ | プロローグにHTMLやスクリプトを入力しても、そのまま実行されない |
| N06 | セキュリティ | 外部へ通信していない。外部のスクリプトを読み込んでいない |
| N07 | 公開 | GitHub Pages 上で、すべての画面と挿絵が表示される |
| N08 | クレジット | 画面とレポートに「いつもの匠」が出る |
| N09 | アクセシビリティ | 記者会見の制限時間を設定で1.5倍・2倍に延ばせ、延長したことがレポートに出る |
| N10 | プレイ時間 | プレイテストで、1シナリオ×1ロールが30〜60分、経営者ロールが30分前後で終わる |

## 7. 内容レビュー（人）

自動検査では分からない「正解の正しさ」を、人が確かめる。

| ID | 確認すること |
| --- | --- |
| R01 | 各判断の正解が、根拠のガイドラインの内容と合っている |
| R02 | ロールごとの正解が、その立場の権限と責任に合っている |
| R03 | 法定期限や報告先が、最新の一次資料と合っている |
| R04 | ミスリードの声が、本物らしく、見分けにくい |
| R05 | 「無難」だけでは高得点にならず、「無謀」でも高得点にならない |
| R06 | 皮肉が、実在の被害企業ではなく「外野の自分」に向いている |
| R07 | 被害企業を「愚か」「自業自得」と受け取れる描写がない。架空の会社も、責められる対象ではなく判断に迷う当事者として描かれている |
| R08 | 全体を遊び終えた人が「悪いのは攻撃者」と受け取れる |
| R09 | 遊び終えた人が、高得点を「現実でも正しくできる証明」と受け取らない |

## 8. セルフチェックリスト（権利・名誉毀損）

外部の法務レビューは行わないため、シナリオごとに公開前に全項目を確認し、結果を記録として残す。

- [ ] 会社名・サービス名・人物名・ロゴ・商品名がすべて架空で、実在の商号・登録商標と重ならない
- [ ] 業種＋時期＋件数＋特徴的な出来事の組み合わせで、実在企業が特定できない
- [ ] 元事件の数字（件数・金額・日数）をそのまま使っていない
- [ ] 元事件で未確定のことを「事実」として描いていない
- [ ] 実在の経営者の発言、報道記事、SNS投稿の文章を転載していない
- [ ] 解説で実際の事件に触れる箇所は、公式発表と公的機関の資料に限り、出典を示している
- [ ] 挿絵がオリジナルまたは利用条件を確認した素材で、実在の人物の写真や似顔絵を使っていない
- [ ] BGM・効果音がオリジナルまたは利用条件を確認した素材で、必要なクレジットを表示している
- [ ] 国家を扱う場面で、特定の国籍や民族への偏見をあおる描写がない
- [ ] 人格攻撃・差別的な表現がない（辛辣さに上限はないが、この線は越えない）
- [ ] 冒頭に「フィクションであり、実在の団体・人物とは関係ない」「悪いのは攻撃した犯罪者」旨を表示している
- [ ] 攻撃者が登場する場面と全エンディングに、「悪いのは攻撃者」の注記がある
- [ ] スコアを出す画面に、「高得点でも現実の対応が正しいとは限らない」注記がある
- [ ] 実在企業の対応を採点・ランク付けしていない。実在企業と比べる文言がない
- [ ] 被害企業（架空を含む）を「愚か」「自業自得」として描いていない
- [ ] 元事件の公式な続報が出揃っている

## 9. プレイテスト

| 項目 | 内容 |
| --- | --- |
| 参加者 | 経営者・役員を中心に、30代以上の会社員（管理職、情シス、セキュリティ担当） |
| 見ること | 1ロールが30〜60分に収まるか（経営者は30分前後）、途中でやめたくなる場面、ミスリードに何人乗ったか、もう一度遊びたいと思ったか |
| 聞くこと | 没頭できたか、音や演出がうるさすぎなかったか、苦しかった場面、爽快だった場面、納得できなかった点数、皮肉が不快だったか、インシデントレスポンスに興味を持てたか、事件のときの批判と対応の見え方が変わったか |
| 合格の目安 | 参加者の半数以上が「もう一度別のロールで遊びたい」と答える |

## 10. 不具合の扱い

| 重さ | 例 | 対応 |
| --- | --- | --- |
| 最重要 | 正解が間違っている、実在企業が特定できる、入力が外部に送られる | 公開を止める。直るまで該当シナリオを非公開にする |
| 重要 | 採点の計算違い、行き止まり、保存が壊れる | 次の公開までに直す |
| 通常 | 表示崩れ、誤字 | 気づいた時点で直す |

## 11. 公開の判定

次をすべて満たしたら、そのシナリオを公開する。

- シナリオ自動検査（C01〜C16）がすべて通っている
- 機能テストと非機能テストで、最重要・重要の不具合が残っていない
- 内容レビュー（R01〜R06）を終えている
- セルフチェックリストを全項目確認し、記録を残している
